# Cloudflare R2 Object Storage Integration Report

## Executive Summary

Cloudflare R2 object storage has been integrated into HeyPrince.in as the primary S3-compatible asset store. The architecture supports Next.js APIs, the Python FastAPI AI backend (`heyprince-ai-backend`), Daily AI News generation, Media Vault, and AI Company documents. Supabase PostgreSQL remains the metadata catalog, ensuring zero binary blobs in the relational database and zero breaking changes for existing media.

## Architecture Overview

- Storage Protocol: S3-Compatible API via `@aws-sdk/client-s3` (TypeScript) and `boto3` / `httpx` (Python).
- High Availability: Automatic fallback to Supabase Storage if Cloudflare R2 is unconfigured.
- Security Model: Public access for website and blog assets; presigned GET URLs (default 1-hour expiry) for private reports, client contracts, and confidential proposals.

## Directory and Folder Structure

Cloudflare R2 buckets are organized into strict folder hierarchies:

- `blogs/`: Published article covers and editorial illustrations.
- `ai-generated/`: Raw generative visuals and diagrams from autonomous agents.
- `company/avatars/`: AI employee profile pictures and executive avatars.
- `company/assets/`: Virtual office floor assets and branding badges.
- `documents/proposals/`: Confidential client proposals generated by Solutions.
- `documents/reports/`: Executive audits, performance reviews, and meeting digests.
- `clients/`: Client uploads and technical assets.
- `media-vault/`: Media cataloged via the admin portal.
- `projects/`: Project deliverables and architectural blueprints.

## Required Environment Variables

The following environment variables configure Cloudflare R2:

```env
R2_ACCOUNT_ID=your_cloudflare_account_id
R2_ACCESS_KEY_ID=your_r2_access_key_id
R2_SECRET_ACCESS_KEY=your_r2_secret_access_key
R2_BUCKET_NAME=your_r2_bucket_name
R2_S3_ENDPOINT=https://<R2_ACCOUNT_ID>.r2.cloudflarestorage.com
R2_PUBLIC_BASE_URL=https://assets.heyprince.in
```

Credentials are kept server-side only. No credentials are leaked to browser bundles or `NEXT_PUBLIC_*` prefixes.

## Implementation Details

### 1. TypeScript Storage Service (`src/lib/storage/r2.ts`)
- `isR2Configured()`: Verifies presence of credentials without throwing exceptions.
- `uploadToR2()`: Validates MIME types against whitelist, enforces 25MB limit for images and 50MB for documents, generates unique collision-resistant keys (`${folder}/${timestamp}-${uuid}-${filename}`), and performs S3 `PutObjectCommand`.
- `downloadFromR2()`: Streams binary buffers via S3 `GetObjectCommand`.
- `deleteFromR2()`: Executes S3 `DeleteObjectCommand`.
- `checkR2FileExists()`: Executes S3 `HeadObjectCommand`.
- `getR2PresignedUploadUrl()`: Signs PUT requests using `@aws-sdk/s3-request-presigner` (default 15 minutes).
- `getR2PresignedDownloadUrl()`: Signs GET requests for private documents (default 60 minutes).
- `getR2PublicUrl()`: Resolves public URLs through custom domain `R2_PUBLIC_BASE_URL`.

### 2. Next.js API Routes
- `src/app/api/admin/storage/upload/route.ts`: Admin multipart upload endpoint with MIME validation, R2 storage dispatch, and Supabase Media Vault cataloging.
- `src/app/api/admin/storage/presigned/route.ts`: Secure presigned URL generator for client-side uploads and private document viewing.
- `src/app/api/admin/media/route.ts`: Updated to prioritize R2 for Media Vault uploads while maintaining Supabase fallback.

### 3. Python Backend Storage Client (`heyprince-ai-backend/app/core/r2.py`)
- Python client supporting S3v4 path-style signatures, file existence checks, presigned URLs, and automatic integration into `generate_cover_image()` in `app/pipeline/image_generator.py`.
